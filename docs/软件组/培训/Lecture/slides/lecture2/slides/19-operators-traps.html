四个高频运算符陷阱

这四类错误几乎每个人都踩过，且编译器多半不会报错——只会安静地给你错误的结果。

if (speed = 0) 的意思是「把 0 赋给 speed，然后判断这个值是否为真」——结果是永远为假； 写成 if (speed = 100) 则永远为真。
解法：把常量写在左边：if (0 == speed)，这样少写一个等号会直接报错。 编译器会给警告 suggest parentheses around assignment used as truth value，不要忽略警告。
只要两边都是整数，结果就一定是整数，小数部分被直接砍掉（不是四舍五入）。
解法：把其中一边变成浮点：5.0 / 2、(float)a / b。 求平均值、算比例时尤其要注意。
C 语言规定：a % b 的结果符号与 a 相同。于是 -5 % 3 = -2，而不是数学上的 1。
解法：需要「始终为正」的余数（环形数组下标、角度归一化）时，写 ((a % b) + b) % b。
== 的优先级高于 &，所以它实际是 a & (b == 0)。
解法：加括号 —— (a & b) == 0。同理 flag & 1 << n 要写成 flag & (1 << n)。
优先级速记（从高到低）： 括号 () → 单目 ! ~ ++ -- (int) → 算术 * / % + - → 移位 << >> → 关系 < > <= >= → 相等 == != → 位与/异或/位或 & ^ | → 逻辑 && || → 赋值 = +=。 记不住就加括号，括号不要钱。
