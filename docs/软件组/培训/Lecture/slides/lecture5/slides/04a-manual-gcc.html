手写编译命令为什么难以维护

一个源文件时，直接调用 GCC 很简单；工程增长后，同一条命令会同时承担文件清单、选项、依赖和链接顺序。

只有 main.c
gcc main.c -o app.exe
增加模块以后
gcc -std=c11 -Wall
  -Iinclude
  src/main.c lib/calc.c
  -DAPP_VERSION=4
  -o app.exe

工程增长带来的问题

命令越来越长：每个源文件、头文件目录和宏都要人工维护。

重复编译：只改一个文件，手写命令仍可能重新编译全部源码。

平台不同：Windows、Linux 与 STM32 使用的编译器和参数不同。

团队难以统一：口头告诉同伴一串命令，很容易漏参数或使用错误版本。

CMake 的作用：把“工程由哪些目标组成、目标依赖什么”写成可提交的配置，再为当前平台生成正确的构建规则。
