「我登录一次为什么到处都能用」的队员。

「按节点放行文件」。** 三者之间只有两条数据流：OIDC 登录、权限命名空间读写。

## 三、三个系统

### 3.1 CAF 认证中心

| 项目 | 内容 |
| --- | --- |
| 源码 | `/www/wwwroot/auth.apoints.cn/dev`（Go + Gin + GORM） |
| 运行 | `/www/wwwroot/auth.apoints.cn/cafserver`（工作目录即此目录，读同目录 `config.json`，静态前端在 `web/dist`），监听 `127.0.0.1:8889` |
| 数据库 | MySQL `caf` 库（users / members / clients / sub_servers / permission_* / user_permission_nodes） |
| 身份来源 | 本地账号 + **LDAP 同步**（启动时同步，约 45 秒，所以刚重启时别急着判定"登录坏了"） |
| 对外能力 | OIDC 授权码流程（`/api/user/login`、`/api/user/oauth/approve`、`/api/oauth/token`、`/api/oauth/userinfo`、`/api/oauth/permission-nodes`）、JWT RS256 签发 |
| 管理界面 | `admin.cas.apoints.email`；官网是它的 **SubServer**（有独立 client_id/secret） |

**本站为它扩展的「权限命名空间」协议**（在原有 OAuth2 基础上新增，源码里的 `models/store/handlers` 各有
一个 `namespace.go`）：

| 接口 | 说明 |
| --- | --- |
| `POST/GET /api/protocol/namespaces` | 建/列命名空间（SubServer 身份） |
| `POST/GET /api/protocol/namespaces/:ns/nodes`、`DELETE …/nodes` | 建/列/删权限节点 |
| `POST/DELETE/GET /api/protocol/namespaces/:ns/grants` | 给用户授权 / 撤销 / 列授权 |
| `GET /api/protocol/namespaces/:ns/candidates?q=` | 搜用户（按 id / 用户名 / 邮箱） |
| `GET /api/oauth/permission-nodes?namespace=…` | **用户侧**：拿自己的节点（带用户 access token） |

三张表：`permission_namespaces`（命名空间，有归属 SubServer）、`permission_nodes`（节点路径）、
`user_permission_nodes`（谁有哪个节点）。节点语义：**点号分层，父节点覆盖子节点**，
`*` 表示该命名空间下全部。

### 3.2 官网 gmaster.team

| 项目 | 内容 |
| --- | --- |
| 组成 | `web/`（Next.js）+ `backend/`（Spring Boot 3.4.5 / Java 21 / MyBatis + JDBC）+ MySQL 8.4 + `feishu-sync` |
| 部署 | `docker compose`，项目目录 `/www/wwwroot/gmaster.xjtlumc.online`，前端映射 `127.0.0.1:3000` |
| 数据库迁移 | Flyway，脚本在 `backend/src/main/resources/db/migration`（目前到 `V38`） |
| 会话 | Cookie `gm_member_session` / `gm_admin`，**SameSite=Lax**（原因见第八节） |

与 CAF 相关的三个部分：

1. **CAF 登录** `CafAuthController`：`/api/auth/caf/start` → CAF 授权页 → `/api/auth/caf/callback`。
   匹配顺序是「先按已绑定的 `cafUserId`，再按邮箱匹配（命中且未绑定就顺手记下绑定）」；
   状态非 `active` 会被挡在门外。
2. **个人资料页绑定** `CafBindingController`：`/api/member/caf/{status,start,callback}`、`/unbind`。
   跨站跳回时会话 Cookie 不会跟着回来，所以 `/start` 会把队员记进服务端的随机票据，回调只认票据。
3. **权限管理后台** `/admin/permissions`（`CafPermissionController` + 前端 `CafPermissionAdmin.tsx`）：
   查看命名空间节点树、给队员授权/撤销、搜人。

**按组别自动授权**：`CafWikiPermissionSync`，只增不减，CAF 报错只记日志不影响登录。触发点三处：

| 触发点 | 时机 |
| --- | --- |
| `CafAuthController.callback` | 队员用 CAF 登录官网成功后 |
| `CafBindingController.callback` | 队员在个人资料页绑定 CAF 成功后 |
| `ManagementController`（members/save） | 管理员改了队员的组别之后 |

### 3.3 文档站 www.gmaster.wiki

```
公开站                               私有站（同一域名，走 /_private/）
┌───────────────────────────┐        ┌──────────────────────────────────┐
│ GitHub: GmasterDoc         │        │ GitHub: GmasterDocPrivate         │
│  push → GitHub Actions     │        │  服务器 timer 每 5 分钟 git pull   │
│  → 服务器 mkdocs build     │        │  → mkdocs build → private_site/    │
│  → GmasterDoc/site（nginx）│        └──────────────────────────────────┘
└───────────────────────────┘                        │
        │                                            │
        └── docs/assets/caf.js + caf.css ────────────┘  （两站共用同一份前端资源）
```

- **公开站**：mkdocs-material 构建的纯静态站，导航写在仓库根 `mkdocs.yml`，产物由 CI 生成（见第六节）。
- **私有站**：内容在私有仓库 `GMasterEmbeddedGroup/GmasterDocPrivate`，服务器工作副本
  `/www/wwwroot/www.gmaster.wiki/private_docs`，构建产物 `private_site/`，
  定时器 `gmasterdoc-private.timer` 每 5 分钟拉取重建（想立刻生效：`bash /opt/gmasterdoc-private/deploy.sh --force`）。
- **鉴权网关**：`/opt/caf-wiki-gate/gate.py`（Python 标准库 + systemd 单元 `caf-wiki-gate`，监听 `127.0.0.1:8137`）。

| 网关配置 | 值 |
| --- | --- |
| `listen` | `127.0.0.1:8137` |
| `protected_prefix` / `private_root` | `/_private/` → `/www/wwwroot/www.gmaster.wiki/private_site` |
| `internal_prefix` | `/__caf_files/`（nginx 内部 location，只由 `X-Accel-Redirect` 触发） |
| `caf.namespace` | `gmaster` |
| `session_store` / `acl_file` | `/var/lib/caf-wiki-gate/sessions.json` / `/etc/caf-wiki-gate/acl.json` |
| `cookie` | `caf_wiki_sid`，HttpOnly + Secure + SameSite=Lax，30 天 |
| `nodes_ttl_seconds` | 300（权限节点缓存 5 分钟；会话 Cookie 30 天内不用重登） |

**为什么是「反代 + X-Accel-Redirect」**：这台 nginx 没编译 `auth_request` 模块，所以改成
网关先鉴权、再让 nginx 从内部 location 直接把文件发出去 —— 大文件不用过 Python 进程。
两个硬约束（代码里都有注释）：`X-Accel-Redirect` 响应**不能带** `Content-Type`/`Cache-Control`
（否则 nginx 透传，浏览器会把 HTML 当纯文本显示）；nginx 转发过来的路径是 `%XX` 形式，
ACL 比对前必须先 unquote。

**前端脚本 `docs/assets/caf.js` + `caf.css`** 干三件事：
①顶栏显示登录态/退出；②处理页面里 `<div data-caf-gate data-src="…">` 的"登录后可见"片段；
③登录后在左侧目录里插一项**内部资料目录**（按权限列出各组入口，未登录时不显示）。
记住它是"界面开关"，真正的拦截在网关。

## 四、权限模型

命名空间 `gmaster`（显示名「GMaster 战队权限」，归属官网这个 SubServer）里现有 12 个节点：

| 节点 | 含义 | 谁来发 |
| --- | --- | --- |
| `site` | 官网 gmaster.team | 手工 |
| `site.admin` | 官网管理后台 | 手工 |
| `site.member` | 官网成员专区 | 手工 |
| `wiki` | Wiki 站点 | 手工 |
| `wiki.admin` | Wiki 站点管理 | 手工 |
| `wiki.private` | 私有文档区（登录后可见） | 手工 |
| `wiki.private.software` | 软件组内部资料 | **自动**：电控组 / 软件组 |
| `wiki.private.mechanical` | 机械组内部资料 | **自动**：机械组 |
| `wiki.private.vision` | 视觉组内部资料 | **自动**：视觉组 |
| `wiki.private.hardware` | 硬件组内部资料 | **自动**：硬件组 |
| `wiki.private.media` | 宣运组内部资料 | **自动**：宣运组 |
| `wiki.private.management` | 管理组资料 | **自动**：`permissions` 含 `management` |

> 官网的组别只有 **机械组 / 硬件组 / 电控组 / 视觉组 / 宣运组** 五种（见 `ApplicationValidator.GROUPS`）。
> Wiki 私有目录叫「软件组」、官网叫「电控组」，**是同一个组**，所以两者都映射到 `wiki.private.software`。

文档站 ACL（`/etc/caf-wiki-gate/acl.json`，改完即生效、不用重启）：

| 线上路径 | 需要的节点 |
| --- | --- |
| `/_private/`（首页） | 登录即可 |
| `/_private/软件组/` | `wiki.private.software` |
| `/_private/机械组/` · `/_private/视觉组/` · `/_private/硬件组/` · `/_private/宣运组/` | 对应 `wiki.private.*` |
| `/_private/管理/` | `wiki.private.management` |
| `/_private/fragments/`（公开站内嵌片段） | 要显式声明 `data-caf-require` 才更严格，否则登录即可 |

规则：**只增不减**。换组别后新组权限加上、旧组保留；要收回请用官网 `/admin/permissions`
或 CAF 管理界面撤销。查某人现在有什么：

```bash
python3 /root/gmq.py --caf "SELECT u.username, n.path FROM user_permission_nodes n JOIN users u ON u.id=n.user_id;"
```

## 五、三条登录路径

```
① 官网登录（gmaster.team）
   浏览器 → /api/auth/caf/start → CAF 授权页 → /api/auth/caf/callback
          → 匹配队员（cafUserId → 邮箱）→ 校验 status=active
          → 按组别补授 CAF 节点 → 种 gm_member_session（Lax）→ 回原页面

② 文档站登录（www.gmaster.wiki）
   浏览器 → /_caf/login?rd=… → CAF 授权页 → /_caf/callback?code=…
          → 换 token、拉 userinfo + permission-nodes → 写服务端会话
          → 种 caf_wiki_sid（Lax）→ 回 rd 指向的私有页

③ 绑定（个人资料页，把"官网账号"和"CAF 账号"钉在一起）
   /api/member/caf/start（记票据）→ CAF 授权页 → /api/member/caf/callback（认票据，不认会话）
   → 写 Member.cafUserId（唯一索引）→ 按组别补授节点 → 跳回 /member/profile?caf=bound
```

三条路径都走 **OIDC 授权码**：本站从不接触密码，access token 只存在服务器端。

**故障排查**

| 症状 | 先看什么 | 常见原因 |
| --- | --- | --- |
| 私有页一直跳登录 | 浏览器有没有 `caf_wiki_sid`；`journalctl -u caf-wiki-gate` | 会话文件属主不对（见第八节）、CAF 挂了、Cookie 被清 |
| 提示缺权限节点 | `user_permission_nodes` 里有没有该节点 | 组别为空 / 没在官网绑定过 / 刚改完组别还没重新登录 |
| 登录后节点是空 | `_caf/me` 返回的 `nodes` | 节点缓存 5 分钟；或官网那次同步失败（看后端日志） |
| 改完前端没生效 | 请求头 `cache-control` | 宝塔给 `.css/.js` 加了 12h 缓存（见第八节） |
| 全站 404 | CI 是否正在跑 | 部署期间 `rm -rf` 旧目录的 40 秒空窗 |
| CAF 登录失败 | `server.log`（CAF 目录下） | 刚重启正在同步 LDAP；或授权回调地址不匹配 |

## 八、已知的坑与约定

1. **跨站跳回会丢 Cookie（SameSite）**：从 CAF 跳回来属于"跨站发起的顶层导航"，
   `SameSite=Strict` 的 Cookie 不会被发送 → 官网会话已改成 **Lax**；写操作另外用
   `api.sameOrigin()` 校验 Origin，安全强度不变。
2. **`X-Accel-Redirect` 不能带实体头**：否则 nginx 透传 `Content-Type`，HTML 会以纯文本显示。
3. **nginx 原样转发 `%XX`**：ACL 与文件匹配前必须 unquote，中文目录名才不会 404。
4. **HTTP 头是 latin-1**：`Location` 不能直接带中文，必须先 `quote` 成 ASCII。
5. **宝塔全局 `proxy_cache cache_one`**：反代型站点一律加 `proxy_cache off`。
6. **`.css/.js` 默认 12 小时缓存**：文档站已做两层处理 —— nginx 给 `caf.js/caf.css` 设
   `expires -1`（协商缓存），并把引用写成 `assets/caf.css?v=YYYYMMDD`。
   **改这两个文件时记得同步改 `?v=`**（公开站 `mkdocs.yml` 与私有站 `private_docs/mkdocs.yml` 各一处）。
7. **网关会话文件属主**：以 root 跑 `gate.py --issue-session` 时若把 `sessions.json` 变成 root 所有，
   以 `www` 运行的网关会读不到 → 所有登录用户当场掉线。程序已修为"落盘沿用原属主"；
   手工改过该文件后记得 `chown www:www`。
8. **文档站部署有约 40 秒空窗**：CI 先删旧目录再 clone+build。想零停机需改成
   "构建到临时目录 + 原子替换"（私有站的 `deploy.sh` 已是这种写法）。
9. **用 mysql 命令行插中文要带 `--default-character-set=utf8mb4`**，否则存成乱码；
   应用自己走 JDBC 不受影响。
