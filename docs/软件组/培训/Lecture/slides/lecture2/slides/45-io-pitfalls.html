输入输出的六个坑

这些错误都不会在编译时报错，只会在运行时「表现得很奇怪」。点击展开。

症状：运行到那一行就闪退 / 提示「程序已停止工作」。
原因：scanf 拿到的是变量的值（比如 0），把 0 当地址去写内存，属于非法访问。
解法：所有基本类型变量都要加 &；只有字符数组（字符串）不用加。
用 %d 打印 float、用 %f 打印 int， 都会按错误的字节数去解释内存。
解法：核对占位符；打开编译器的 -Wall 选项，它会提示 format '%d' expects argument of type 'int'。
症状：连续输入时程序「跳过了」某一步。原因见上一页的输入缓冲区。
解法：读字符用 scanf(" %c", &c);（前面加空格），或先 getchar(); 吃掉换行。
源文件用 UTF-8 保存，而 Windows 终端默认用 GBK 解释字节，于是中文变成「锟斤拷」一类字符。
解法：编译时加 -fexec-charset=GBK，或把终端编码切成 UTF-8 （PowerShell 执行 chcp 65001）。教学阶段更省事的办法：先用英文输出调试信息。
printf("请输入："); 后面没有换行，光标停在提示语右边等着你输入 —— 这是正常的。反过来，如果你在 scanf 之前写了很多没有换行的输出，界面会显得很乱。
解法：输入前不换行（提示更紧凑），结果输出后换行。
if (n = 5) 把 5 赋给 n 并判断 5 是否为真 —— 永远成立。
解法：常量写左边：if (5 == n)；并且认真读编译器给出的 suggest parentheses 警告。
