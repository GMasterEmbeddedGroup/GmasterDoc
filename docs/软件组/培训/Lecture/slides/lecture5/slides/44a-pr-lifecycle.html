Pull Request 的评审周期

PR 不是上传后等待合并的静态表单。它把同一个开发分支的后续提交、讨论和自动检查集中在一起。

创建 PR说明背景与验证
→
自动检查构建 / 测试 / 格式
→
代码评审逐行意见与问题
→
继续提交push 同一分支
→
批准合并进入 upstream/main
收到修改意见在本地原分支修改、构建、提交并 push。已有 PR 会自动显示新提交，无需重新创建。
上游出现更新先 fetch upstream，再按团队约定 merge 或 rebase；解决冲突后重新验证。
PR 被合并切回 main，同步 upstream/main；确认不再需要后再删除开发分支。
可评审的 PR：一个主题、差异范围小、说明包含验证命令，并且不混入生成物、密钥或无关格式化。
