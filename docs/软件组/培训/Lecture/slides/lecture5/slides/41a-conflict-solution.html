冲突解决实例

main 希望默认关闭跟踪，dev/trace 希望默认开启。解决冲突不是机械选择一边，而是确定项目真正需要的最终内容。

编辑后的最终内容
# 默认关闭，调试时用 -D 开启
option(ENABLE_TRACE
    "Print debug trace"
    OFF
)
$ git add CMakeLists.txt
$ cmake -S . -B build \
-DENABLE_TRACE=ON
$ cmake --build build
$ git commit

处理顺序

1. 理解两边意图：默认值应保持 OFF，但仍允许开发者显式开启。

2. 写出最终文件：删除所有冲突标记，不能把 <<<<<<< 留进源码。

3. 验证行为：分别检查默认配置与开启 Trace 的构建。

4. 标记解决：git add 表示你已经确认最终内容，再完成合并提交。

需要退出时：尚未完成合并可用 git merge --abort 返回合并前。不要用 reset --hard 代替，因为它还可能丢弃原有未提交修改。
